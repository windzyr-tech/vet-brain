# 标准文档结构

## 示例

```markdown
---
title: "头颈部血液供应"
description: "头颈部主要动脉与静脉的解剖学笔记，基于 2024 年课程资料。"
category: "解剖"
date: "2026-11-22"
language: "zh"
needsTranslation: false
---

# 头颈部血液供应

> **摘要**：本文整理头颈部主要动脉与静脉的来源、走行与分布，便于复习与检索。

## 目录

- [颈总动脉](#颈总动脉)
- [主动脉相关分支](#主动脉相关分支)
  - [颈外动脉的分支](#颈外动脉的分支)

## 颈总动脉

具体内容……

## 主动脉相关分支

具体内容……
```

## 字段要求

| 位置 | 要求 |
| --- | --- |
| `title` | 必填，与正文 H1 一致 |
| `description` | 必填，1～2 句话概括全文；同时显示在标题下方 |
| `category` | 必填，用于分类浏览 |
| `date` | 建议填写 |
| H1 | 全文唯一一个 |
| 摘要块 | `> **摘要**：...`，紧跟 H1 |
| 目录 | 长文必填，位于摘要之后、正文之前 |
| H2 / H3 | 按内容逻辑分层，不跳级 |
| 样式 | 不允许残留内联 `style`、`font` 标签 |

## 为什么需要目录

很多课件和教材转换后是大段连续文字，读者很难判断文章结构。长文目录让打开文档的人一眼看到全篇脉络，也能快速跳到关心的小节。

## 自动修复的边界

脚本会补齐缺失字段、添加 H1/摘要/目录、去除内联样式、统一标题间距；但不会：

- 改写专业内容或结论
- 翻译文字
- 调整事实性表述
- 修改来源与哈希字段

因此自动修复后仍需人工复核摘要与目录是否真正贴合内容。
